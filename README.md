# Enright Design Foundry

Portfolio site for enrightdesignfoundry.com, rebuilt from Webflow in Vite + React + TypeScript + Tailwind CSS v4.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # production build in dist/
npm run preview    # serve dist/ locally
```

## Working on dev (nothing reaches the live site until you merge)

Two branches: `main` is the live site, `dev` is where changes happen. Every push to `dev` publishes a preview at **https://enrightdesignfoundry.com/dev/** (it carries a red DEV tag and is hidden from search engines); the live site is rebuilt from `main` in the same run and doesn't change.

```bash
git switch dev          # work here
npm run dev             # http://localhost:5173 while you work
git push                # preview at enrightdesignfoundry.com/dev/ in a minute or two
```

When the preview looks right, make it live:

```bash
git switch main
git merge dev
git push                # live site updates
git switch dev          # back to work
```

If a `dev` push won't build, the "Dev preview" check on GitHub fails and nothing is published. The live site is never affected by `dev`.

## Adding or changing a project

1. Put the original images in `media-src/design/thumbs`, `media-src/design/full` (or `media-src/video/thumbs`).
2. Run `npm run media`. It writes optimized AVIF + WebP files to `public/media/` and records sizes in `src/content/media.json`.
3. Add or edit the project in `src/content/projects.json`. The key under `asset` is the image's path inside `media-src/`.

Without the whole `media-src/` folder (`npm run media` rebuilds everything from it), add images one at a time instead: `npm run add-media -- <image> <key>`, e.g. `npm run add-media -- ~/Desktop/candescent.png design/thumbs/candescent.png`. It makes the same AVIF + WebP sizes and adds or replaces just that image in `media.json`. Keep the originals in `_for-media-src/` (same folder layout; not committed).

Everything else (strip length, panels, viewer, deep links) follows from the data. A side can have any number of projects.

`media-src/` holds the full-resolution originals and is not committed (it's in `.gitignore`); keep a backup of it somewhere. If it's missing, `download-webflow-assets.sh` from the rebuild plan pulls everything from Webflow while that site is still up.

### Project fields

| Field | Used for |
|---|---|
| `id` | Deep link: `#design/tempest` opens that project |
| `category` | `design` or `video` |
| `order` | Position in its row |
| `title`, `discipline` | Design projects |
| `title`, `duties`, `crewSize`, `timeline` | Video projects |
| `description` | Text behind the DESCRIPTION button |
| `thumb` | `{ "type": "image", "asset": ... }` or `{ "type": "lottie", "src": "/lottie/....json" }` |
| `media` | Images (`asset`) or YouTube (`youtubeId`, `title`, `poster`) shown in the viewer. Add `"split": true` to an image made of two halves side by side: on phones and portrait tablets the viewer stacks the left half above the right half (only when that shows it larger). `"split": "right-first"` puts the right half on top. Add `"portrait": "<key>"` for a separate tall layout of the same board (Candescent): the viewer shows whichever layout comes out larger, so phones and upright tablets get the tall one |
| `link` (optional) | Extra viewer button: `{ "label": "Visit site", "href": "/nsyte/" }` opens in a new tab (any URL, e.g. a YouTube channel). Add `"download": "Miami.ttf"` and `"downloadTitle": "Download the Miami Typeface"` to make it open a small download popup instead (files live in `public/downloads/`) |
| `alternate` (optional) | Second view swapped in with its own button: `{ "label": "Watch video", "backLabel": "See design", "media": ... }`. The artwork slides up and away and the new view slides up into its place; the button then reads the back label. `media` can be YouTube media, an image (`{ "type": "image", "asset", "alt" }`), or a document: `{ "type": "document", "alt", "pages": [page image keys] }`, shown as a scrolling column of pages (landscape pages fit the screen, portrait pages run at a 1000px reading width). For a PDF, render its pages into `media-src/` (e.g. `pdftoppm -r 240 -png deck.pdf media-src/design/full/deck/page`) and run `npm run media`. Scrolling swaps too: scroll (or swipe, or press Down) on the main view and the card gives a little, then the alternate snaps up; scroll up on the alternate (at the top of a document) to go back. A document also shows a "scroll down" cue, the hero's scroll hint in a gray circle, until its pages are scrolled |

`poster` is the YouTube preview frame size that exists for that video: `maxresdefault`, or `sddefault` for older uploads without an HD frame.

## Nav button art

The DESIGN, VIDEO and RESUME buttons are Jim's Illustrator frames, played as a flipbook.

1. Export each frame's artboard as SVG (Export for Screens) into `button-art/<button>/SVGs/` (or a subfolder named by `dir` in `frames.json`, like `SVGs/BotLeft`) (`design-wide`, `video-wide`, `resume-wide`, `design-square`, ...). Every frame of a button shares one artboard size. Square art is shown at the same height as the wide art, so a square artboard as tall as the wide one (407) keeps line weights identical.
2. `button-art/frames.json` says which artboard numbers play when: `frames` in hover order (first = resting, last = held end frame; list a number twice to hold it longer), `active` for the selected category, `fps`, and `color` (the shapes are exported unfilled and draw in this color; `#1d262c` is the logo's ink).
3. Run `npm run buttons`. It writes `src/assets/buttons/` (one SVG per hover frame, `<button>-frame-0.svg` onward, plus `<button>-active.svg`) and `src/content/buttonArt.ts`.

The artwork is never altered: each frame's markup is copied verbatim into its own wrapper, which only sets the color, and the script checks that. Only the exported SVGs and `frames.json` are committed; the `.ai` files and PNG renders in `button-art/` are ignored.

## How it's built

- `src/components/DesktopGallery.tsx`: 992px and wider on landscape screens (at least 5:4). The strip (and the page's scroll length) is as long as the side that's showing, measured from that side's own row (`measureFor`), so DESIGN and VIDEO can each have any number of projects; switching re-measures in the same frame, so nothing on screen jumps. Vertical scroll moves one long strip sideways (hero, nav column, panels), using the same linear mapping as the Webflow interaction. Sideways input works too: trackpad swipes and Shift + mouse wheel (down or right goes forward, up or left goes back). The left / right arrow keys step one stop at a time (hero, nav column, then each panel). Keyboard focus (Tab) slides the strip to whatever it lands on; the strip container uses `overflow: clip` so the browser can't scroll it sideways on its own. Switching DESIGN / VIDEO starts the new side at its beginning, the same spot as scrolling away from the hero (full nav column at the left edge, first panel just to its right, so scrolling on plays the same hold-then-collapse): in the same frame as the switch the page scroll goes back to that start and the side being left is nudged sideways by the same amount, so nothing on screen jumps; then the usual slide runs while the rail opens back to full width.
- The desktop nav column (`NavColumn` in `src/components/Nav.tsx`, `.rail` in `index.css`) rides in the strip until its left edge reaches the screen edge, then pins there; the first panel slides under it, and when that panel reaches the docked rail's edge the column collapses to a slim docked rail (0.3 s, the same motion as the hover open), opening again when scrolled back past that point. The buttons keep their height and only get narrower, ending as squares; sizes come from the button art (`src/lib/rail.ts`). Moving the mouse onto the docked rail, tabbing into it, or clicking / tapping it opens it back up over the work; it closes 0.25 s after the pointer leaves. The logo's size follows docking only, so opening the docked rail never moves the buttons under the pointer; opening it turns the logo into the logotype lockup (`src/assets/brand/edf-logotype-lockup.svg`) at the buttons' width, centered between the top of the rail and the rule: the anvil fades out and the wording grows upward, its "design foundry" crossfading into the lockup's bar while ENRIGHT (the same in both files) stays solid (`.logo-mark`, `.logo-words` in `index.css`). The buttons can only be clicked in their wide form. Clicking the logo glides back to the hero, docked or not. Clicking RESUME folds the rail straight back to docked, so About lands beside it rather than under the opened rail, and hovering doesn't reopen it until the pointer has left the rail once. The wide and square art crossfade. Below the bottom rule, CONTACT shrinks to fit the docked rail, grows slightly on hover, and opens the contact popup. Every button has square art (`design-square`, `video-square`, `resume-square`). RESUME sits at the bottom, above the rule over CONTACT, and shows the about / resume slides as the strip's third side (`onResume`; see below). While they show, RESUME has its selected art (`resumeActive`) and neither DESIGN nor VIDEO does (`categoryActive`); either one switches back to that side.
- `src/components/MobileGallery.tsx`: under 992px, and any screen narrower than its height plus the docked rail (about 1.07 times as wide as it is tall; `STRIP_QUERY`), where a whole square panel wouldn't fit beside the rail: portrait iPads and monitors, squarish windows. Normal vertical page. The DESIGN / VIDEO | RESUME row is at the top of the page and stays stuck there (`--mnav-h`). The hero fills the rest of the first screen (`.mobile-hero` in `index.css`), with CONTACT (the contact popup) right under the lockup, the two centered together. As the page scrolls, the lockup and CONTACT hold still while the work (or About) slides up under them; when it's twice the lockup-to-button gap below CONTACT (40px; 24px on short screens), it all scrolls on together and the hero leaves, and scrolling back plays it in reverse (`PinnedHero` in `Hero.tsx`, `.hero-pinned` / `.hero-group` in `index.css`: `position: sticky`, centered by the pair's measured height, `--hero-g`). The hand-off is eased: over about a third of a screen of scrolling, centered on the point where sticky lets go, the pair starts slowly and its speed rises evenly to the page's, ending exactly where sticky alone would put it (`easeLift`; a scroll-driven animation in Chrome and Safari, `.hero-pinned[data-ease]`, and a scroll handler in Firefox). Phones lying on their side have no room to spare, so there it simply scrolls. The work is a grid of square tiles: one across on phones, two on tablets, and on screens lying on their side as many as it takes for a whole tile to fit (two, or three on long phones) (`useColumns`). After the work, an ink ribbon has a cream CONTACT button (a cream outline on hover). Each side is only as tall as its own tiles (the box holding both takes the showing side's height), so either side can have any number of projects. DESIGN / VIDEO slides the sides sideways; switched while scrolled into the work, the new side starts at its first tile. Thumbnails are grayscale until hovered wherever there's a mouse (`.thumb` in `index.css`, `(hover: hover) and (pointer: fine)`), in this layout and the desktop strip alike; touch screens, which can't hover, show them in color.
- `src/components/ProjectViewer.tsx`: one native `<dialog>` for every project. Opening is CSS animations (`.viewer-backdrop`, `.viewer-slide`, `.viewer-controls`, `.viewer-caption` in `index.css`): the backdrop dims, the artwork slides up, the close button slides in from the right, and the caption bar rises in a beat (160ms) after the artwork. The pointer stays a normal arrow (a hand when dragging zoomed artwork). Duration and curves are the `--viewer-*` variables on `.viewer`. Clicking the artwork closes it (drags and text selection don't). Nothing sits on top of the artwork: the close button is alone in the top corner, and everything else is in the caption bar under the artwork (`CaptionBar`): the project's title and discipline, DESCRIPTION, and the project's extra buttons (`link`, `alternate`), all solid ink with a sand outline. On phones the title sits above a full-width row of buttons (long labels wrap inside them) and the artwork rests on the bar. Pictures and videos keep clear of the close button above them and stand off the caption bar below (`TOP_BAND_WIDE`, `STAGE_GAP`, `STAGE_INSET`). DESCRIPTION (D key; only for projects with description text) opens the text (`DescriptionSheet`) as a panel down the right side on screens lying on their side, or as a drawer under the caption bar on tall screens; the artwork re-fits into what's left, so the text never covers it and can stay open while a video plays. The text follows the resume's hierarchy: the title in DDC Hardware, small tracked DDC labels, reading text in League Spartan. Pinching zooms only the artwork (`usePinchZoom`); on touch screens a double tap zooms in on that spot (2.5x) or back to fitted, and a single tap closes after a 280ms wait for a second tap (`useTapToClose`; a mouse click closes straight away): two fingers or a trackpad pinch, one finger or a mouse drag to look around once zoomed, back to normal when pinched small; the page and the viewer's buttons never zoom (`touch-action: none` on the viewer), and a tap on zoomed artwork doesn't close it. Document pages zoom by widening the column, then scroll both ways (`useDocumentZoom`). On touch screens the caption bar also has [ + ] [ fit ] [ - ] (`ZoomButtons`, beside the title on phones, after the other buttons on tablets), so people find out the artwork zooms: + and - step by 1.6x around the middle of the view, fit goes back to the whole board, and fit and - sit dimmed while it's already fitted. Boards with `"split"` stack their halves on any screen taller than it is wide. The description starts closed every time the viewer opens. Esc closes the description first, then the viewer; the back button closes it too.
- `src/components/ButtonArt.tsx`: the nav buttons (see Nav button art). On touch screens the frames run at half speed (`--art-slow` in `index.css`), and a tapped button plays its press through before showing its selected frame (there's no hover to warm it up). Each button's frames are stacked in one box, drawn exactly like the selected frame, and only the current one shows (so the end of the hover and the selected frame line up to the pixel); hovering with a mouse, trackpad or pen (not touch) or keyboard focus runs `--art-frame` (a whole-number CSS property) from the first frame to the last at the art's frame rate, and leaving runs it back from wherever it got to. The selected category shows its active frame. With reduced motion it cuts straight to the end frame. (`LottieButton.tsx` and `public/lottie/design-btn.json` / `video-btn.json` are no longer used.)
- Popups (`src/components/Popup.tsx`): a box with a sand outline on ink over a dimmed page, like the viewer's download popup. A native `<dialog>`, drawn by `App.tsx` outside the gallery and opened from anywhere (`openContact()` in `src/lib/contact.ts`). Esc, the close button or a click outside closes it; the backdrop fades and the box rises in (`.popup-*` in `index.css`), and with reduced motion it just fades. While one is open the page behind doesn't scroll.
  - `ContactDialog.tsx` (CONTACT): "How can I work with you?", a line in League Spartan, and a message form (`ContactForm.tsx`: name, email (the one required field, marked *), message, and SEND centered under them). If a send fails, the note under SEND asks to try again (Jim's email address is nowhere on the site, by his choice, 2026-11-21). The form sends through the EDF form relay (`form-relay/`, see its README): a Cloudflare Worker that checks Cloudflare Turnstile (the bot check, `src/lib/turnstile.ts`, loaded only once someone starts on the form and invisible unless it needs a click) and a hidden `website` field only bots fill in, then emails Jim with Reply set to the visitor, storing nothing. Its address and Turnstile site key are `forms` in `site.json`. Typing works normally in the popup's fields (the popup's scroll-key blocking skips form fields).
- About / resume panel (`src/about/`): part of the portfolio page, not a page of its own. Links: `/#about` opens it on About, `/#about/resume` on the resume; the old `/about/` address forwards there (`about/index.html`, `src/about-main.tsx`). Opening it adds a history entry, so the back button closes it (`useAboutHash` in `src/hooks/`). Two slides, About then Resume.
  - Desktop (`AboutRow` in `AboutLayer.tsx`, `side` in `DesktopGallery.tsx`): the strip's third side. RESUME slides About and the resume in from the right (DESIGN and VIDEO slide in from above and below), with the rail docked beside About; DESIGN or VIDEO pushes them back out the way those two push each other (DESIGN drops in from above and pushes them down, VIDEO rises from below and pushes them up, 0.25s, `PUSH_DURATION`), the new side starting at its beginning while the rail opens back up; if the strip was nearer the hero, it glides on until the rail docks. The page scrolls through them exactly like the work: down or right to the resume, and back up past About to the nav column and the hero. Between About and the resume, a scroll that stops part-way carries on to the slide it was heading for (40px is enough, `ABOUT_COMMIT`; one mouse-wheel step does it) or back to where it started. A resume taller than the screen scrolls on its own once it's fully in, and scrolls on back to About from its top. Resizing the window keeps the same slide on screen.
  - Phones and portrait screens (`AboutStack`, in `MobileGallery.tsx`): RESUME (in the DESIGN / VIDEO row) slides the panel in from the right in place of the work: About, then the whole resume down the page. DESIGN or VIDEO slides it back out. Windows lying on their side that still get this page (squarish windows, small laptops) keep the desktop About composition (`.about-frame`), at most a screen tall: when the portrait is shorter than the screen, the section keeps only half the leftover space above the head; phones and upright screens get the portrait, then the letter.

## Deploying

`.github/workflows/deploy.yml` publishes to GitHub Pages on every push to `main`. Each run builds `main` at the root and `dev` at `/dev/` (with `SITE_ENV=dev`, which adds the DEV tag and `noindex`; see `vite.config.ts`). A push to `dev` runs `.github/workflows/dev-preview.yml`, which checks that `dev` builds and then starts the Pages workflow on `main` (Pages only accepts deploys from `main` by default, so `dev` never deploys by itself). A broken `dev` build leaves the preview out of a `main` deploy rather than blocking it.
Set the repo's Pages source to "GitHub Actions". The site is served from the custom domain (Settings > Pages > Custom domain: `enrightdesignfoundry.com`; DNS at Porkbun points the root at GitHub Pages' four addresses and `www` at `pmenright.github.io`), so the workflow builds with `BASE_PATH` `/`. For a test copy at `USERNAME.github.io/REPO/` without a custom domain, `BASE_PATH` would be the repo's sub-folder instead.
